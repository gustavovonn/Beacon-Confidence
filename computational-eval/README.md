# F2MD Offline Evaluator & Benchmarks

Decoupled reference implementation of F2MD and offline evaluator comparing OLS-CTRA + Beta-Reputation against baseline algorithms.

---

## 1. Directory Structure

```
computational-eval/
├── CMakeLists.txt                 # Build configuration (no Arrow; optional -DSTATIC_BUILD=ON)
├── offline_evaluator.cc           # Benchmark app: trace loading, stage probes, tier driver
├── requirements.txt               # Python ETL dependencies (pandas, pyarrow, scipy)
├── include/
│   ├── BsmRecord.h                # Format-neutral decoded beacon record
│   ├── BinaryTraceReader.h        # .bin parser (zero dependencies)
│   ├── BsmAdapter.h               # BsmRecord -> BasicSafetyMessage / ReceivedVector
│   ├── F2MDEngine.h               # F2MD baseline checkers + reputation apps
│   └── BasicSafetyMessage.h, omnetpp.h   # Veins/OMNeT++ shims
├── scripts/
│   ├── interpolate_veremi.py      # Raw JSON -> synchronized Parquet
│   └── export_parquet_to_bin.py   # Parquet -> zero-dependency .bin
├── veremi/                        # Generated by the ETL
│   ├── parquet/                   # Columnar traces (.parquet, ETL intermediate)
│   └── bin/                       # Binary traces (.bin)
└── veins/                         # Decoupled F2MD checks & applications
```

The confidence mechanism itself comes from the repository's shared `include/` and `src/`, and the
motion primitives from `libs/v2x-misc/`. RISC-V packaging lives in `vf2-setup/`.

---

## 2. Data Preparation Pipeline

Raw simulation traces live in `<repo_root>/veremi-extension/data/` (produced by
`veremi-extension/run_pipeline.sh`). All scripts use dynamic relative paths.

### Python Virtual Environment Setup
Install the required ETL packages (`pandas`, `pyarrow`, `scipy`):
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### Trace Ingestion & Binary Export
```bash
# 1. Parse raw JSON traces into synchronized Parquet (all 8 profiles by default):
python3 scripts/interpolate_veremi.py

# 2. Convert Parquet to zero-dependency binary traces (veremi/bin/):
python3 scripts/export_parquet_to_bin.py
```

*Options for `interpolate_veremi.py`: `--profile <name>` (single profile), `--max-msgs 50000`, `-j <workers>`.*

## 3. Build

### Host Build (Zero Dependencies)

The evaluator ingests only the zero-dependency binary traces (`.bin`), so no Apache Arrow
or Parquet C++ libraries are required. Produce the traces with the ETL step above.

```bash
cmake -B build -S .
cmake --build build -j$(nproc)
```

### RISC-V Cross-Compilation
```bash
cmake -B build-riscv -S . \
    -DCMAKE_SYSTEM_NAME=Linux -DCMAKE_SYSTEM_PROCESSOR=riscv64 \
    -DCMAKE_C_COMPILER=riscv64-linux-gnu-gcc \
    -DCMAKE_CXX_COMPILER=riscv64-linux-gnu-g++ \
    -DSTATIC_BUILD=ON
cmake --build build-riscv -j$(nproc)
riscv64-linux-gnu-strip build-riscv/offline_evaluator -o build-riscv/offline_evaluator_stripped
```

For the full VisionFive 2 flow (BusyBox userland, initramfs packaging and TFTP deployment of
the kernel, device tree and initramfs), use `../vf2-setup/vf2_setup.sh`, which runs this build
for you.

## 4. Running Benchmarks

### Automated Runner (Evaluates All 8 Profiles by Default)

`vf2-setup/run_benchmarks_riscv.sh` is packed into the initramfs as `/bench/run_benchmarks_riscv.sh`
and runs on the board:

```bash
cd /bench && ./run_benchmarks_riscv.sh --max-msgs 50000

# (Optional) Evaluate a single profile instead:
./run_benchmarks_riscv.sh --profile ConstPos_0709 --max-msgs 50000
```

On the host it also works from `vf2-setup/`, picking up `computational-eval/build*/offline_evaluator`
and `computational-eval/veremi/bin/`.

### Direct CLI Execution

```bash
./build/offline_evaluator --tier <1|2|3|all> --stage1 <checker> --stage2 <app> --dir <dataset> --profile
```

`--csv-out <path>` appends one CSV row per run; the automated runner writes its CSV and Markdown
summaries to `results/` (on the board, `/bench/results`, a tmpfs).
